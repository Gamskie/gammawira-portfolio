Compressing container booking from 4 hours to 10 minutes

An end-to-end AI automation pipeline for an Indonesian commodity briquette exporter — parsing IPL templates, computing holiday-aware shipment dates, generating shipping documents, and submitting bookings to MSC, Maersk, ONE, Evergreen, and ZIM.

The problem

For every container shipment, the export team was running the same flow by hand. Sales would drop an Instruction Packing List (IPL) — a Word or Excel template with order details. From there: parse the goods + buyer, compute the shipment date around Indonesian + destination-country holidays, generate Invoice / Packing List / B/L drafts, compose a routing-aware booking email to the right carrier, and submit the booking through that carrier's portal.

Four hours per container, multiple containers per week. And every step was fragile — a typo in dates, the wrong carrier picked, a missed holiday — would burn another half-day of back-and-forth.

The architecture

The system is a Python pipeline orchestrating six stages:

IPL (xlsx/docx) → Parser → Date Engine → Doc Generator → Email Composer → Carrier Submitter → Audit Log
  • Parser — reads IPL Excel/Word using openpyxl + python-docx. Uses a prefer_below lookup convention so it tolerates layout drift between Sales' templates.
  • Date engine — holiday-aware shipment math. Pulls Indonesian + destination-country holidays, applies cutoffs (CY closing date, ETD, ETA), and outputs a complete date set per booking.
  • Doc generator — fills Invoice, Packing List, COA, COO, B/L draft templates with merged fields. Uses Win32 COM for cases where Word formatting must round-trip exactly.
  • Email composer — Claude API drafts a routing-aware email per carrier, picks the right contact, and attaches the generated docs.
  • Carrier submitter — Playwright drives the booking portals (MSC instant-booking, Maersk MyFinance, ONE Quote, Evergreen Shipmentlink, ZIM Schedule). Headed mode for portals that need session continuity, headless for the rest.
  • Audit log — every step writes to SQLite, so any booking can be traced end-to-end if something goes wrong downstream.

The hard parts

1. Layout drift in IPLs

Sales templates aren't rigid. The "Buyer" cell could be at B5 in one file and C7 in another. I built a prefer_below resolver that anchors on label cells and walks down, with a regex fallback. It now parses ~98% of IPLs cleanly without manual intervention.

2. Holiday calendars per country pair

ETD (Estimated Time of Departure) for an Indonesia → Hamburg shipment via MSC isn't just "5 days after CY cutoff." It needs to account for the carrier's vessel schedule, plus public holidays at origin port (Tanjung Priok / Surabaya), transshipment hub (Singapore / Tanjung Pelepas), and destination port. The date engine carries a holiday table per port and adjusts for non-business days at every leg.

3. Routing-aware email composition

Different carriers have different intake formats. MSC wants a structured booking request; ONE wants a quote first; Evergreen takes a free-text email but parses it strictly. I use Claude with a system prompt that includes the routing rules as JSON, plus a few-shot example per carrier. Output gets validated against a schema before send.

4. Browser automation that actually survives

Carrier portals are notorious for breaking automation. I split into three reliability tiers — high (MSC, ONE: stable DOMs, work headless), medium (Maersk: needs cookie persistence, work headed in CI), unstable (Evergreen, ZIM: session timeouts, fall back to email submission with a Loom-recorded confirmation). The pipeline picks per carrier instead of failing the whole booking.

The stack

  • Python 3.11 as the orchestrator
  • openpyxl + python-docx for spreadsheet/Word parsing
  • Win32 COM for high-fidelity Word/Excel generation on Windows
  • Claude API (Sonnet 4.6) for email composition + routing decisions
  • Playwright for carrier portal automation
  • SQLite + FTS5 for the audit log + full-text search across past bookings
  • FastAPI + a lightweight HTML dashboard for ops to monitor in-flight bookings

The result

The team books in ~10 minutes, end-to-end. They paste an IPL into the dashboard, review the auto-generated docs and the drafted email, click submit. The system handles parsing, dates, doc gen, carrier choice, submission, and confirmation logging.

Saved time compounds: ~20 hours/week now goes back to the team for higher-leverage work — relationship building with buyers, negotiating new carrier contracts, expanding to new destinations. That's the actual ROI, not just the booking speed.
